# Заметки о WiFi-боксе Creality

[English](BOX-NOTES.md) | [繁體中文](BOX-NOTES.zh-TW.md) | Русский

Здесь собраны сведения о `CXSWBox` (прошивка V3.04b06), подключённом к принтеру
по USB и к сети по Ethernet. Полный снимок работающего бокса (бинарники, сценарии,
конфигурация) хранится на рабочей станции в `/tmp/box_snapshot/` и может быть
использован для восстановления.

## Доступ

- API состояния на порту 81: `/protocal.csp?fname=Info&opt=main&function=get`
- Анонимный FTP к SD-карте бокса (`/mmcblk0p1/`)
- telnet (учётные данные зависят от устройства и здесь не приводятся)

Бокс работает на MediaTek RT2880 / Linux 2.6.36 (SDK). Его демон `prt_com`
владеет `/dev/ttyUSB0` (CH341, 115200 бод) и опрашивает принтер командами
`M105`/`M27`/`M31`. Прямая запись в последовательный порт работает ненадёжно,
если этот демон не запущен.

## Образ прошивки

`cxsw_update.tar.bz2` — официальный пакет прошивки бокса: образ U-Boot с ядром
и зашифрованной/обфусцированной корневой ФС (высокая энтропия, нет узнаваемых
сигнатур squashfs/JFFS2), `install.sh` и writable-каталог `rw_dir/`. Исходного
кода `prt_com` в нём нет, и сравнение корневой ФС с работающим боксом не даёт
дерева исходников для патча.

## Встроенный MCU OTA (не пригоден для этой платы)

В боксе есть процедура MCU OTA, запускаемая FIFO-командой `mcu_ota`:

1. Ищет `creality/mcu_ota.bin` на своей SD-карте.
2. Отправляет принтеру `M936 V2` и ждёт `mcu reset ok`.
3. Передаёт прошивку загрузчику.

На плате 4.2.7 это не работает: в оригинальной прошивке Creality 4.2.7 нет
обработчика `M936`, а загрузчик не переходит в режим OTA. Даже после добавления
`M936` и патча цикла ожидания переданные байты воспринимались Marlin как
недопустимые команды. Этот путь не используется.

## Рабочее решение: Marlin BFT

В Marlin 2.1.2.10 включён `BINARY_FILE_TRANSFER` (`M28 B1 <file>`).
Постоянный загрузчик на боксе управляет им:

- Загрузочный хук `/mnt/creality/custom_start.sh` (зарегистрирован в `_md5_app`)
  запускает `bft_daemon.sh` при каждой загрузке бокса.
- В `creality/bft/` лежат подготовленные `stream_<sync>.bin`, `packets_<sync>.txt`,
  `close_<sync>.bin` и `sync.bin` для всех 256 значений sync.
- Создание `creality/bft/trigger` запускает передачу. Загрузчик временно
  подключает безмолвный `prt_com`, входит в бинарный режим, передаёт по одному
  целому пакету с интервалом ~30 мс (BusyBox `sleep` не умеет дроби, поэтому
  используется `awk`), проверяет >1700 ответов `okN`, отправляет CLOSE, затем
  `M21` и `M997`, после чего принтер перезагружается и загрузчик устанавливает
  прошивку. Оригинальный демон восстанавливается после передачи.
- Ход передачи и ошибки пишутся в `creality/bft/result.txt`.

Ключевые детали, сделавшие передачу надёжной:

- Никогда не разбивайте BFT-пакет на несколько записей — Marlin ждёт остаток и
  истекает по таймауту.
- Не запускайте `stty` во время передачи: открытие/закрытие порта переключает
  DTR и перезагружает плату Creality.
- Опросные команды демона `M105`/`M27`/`M79`/`M930`/`M115` портят бинарный поток,
  поэтому на время передачи демон заглушается.
- Ответы из лога нужно читать с нового смещения; старые строки `ok`/`rs` дают
  ложные срабатывания.
