# Прошивка Ender-3 / Creality v4.2.7 + CR-Touch

[English](README.md) | [繁體中文](README.zh-TW.md) | Русский

Пользовательская прошивка [Marlin 2.1.2.10](https://marlinfw.org/) для **Ender-3** с:

- **32-битной платой Creality v4.2.7** (STM32F103RET6)
- **Датчиком CR-Touch** для авто-калибровки стола (совместимый клон BLTouch)
- **Комплектом удлинения оси Z** — ход Z 350 мм (профили Creality «Z350»)
- Стандартной конфигурацией LCD/дисплея

Основная ветка разработки —
[`upgrade-marlin-2.1.2.10-crtouch`](https://github.com/van-thieu/Ender-3-427/tree/upgrade-marlin-2.1.2.10-crtouch).
Ветка `master` осталась неизменной (исходная импортированная версия).

## Основные настройки прошивки

| Параметр | Значение | Назначение |
|---|---|---|
| `MOTHERBOARD` | `BOARD_CREALITY_V427` | 32-битная плата Creality 4.2.7 |
| `BLTOUCH` | включено | CR-Touch — клон BLTouch: сигнал PB1, серво PB0 |
| `BLTOUCH_DELAY` | `500` | Дополнительная задержка команд для клона датчика |
| `NOZZLE_TO_PROBE_OFFSET` | `{ -30, 0, 0 }` | Измерено по «живому» `M851` принтера (X-30, Y0); Z калибруется во время работы |
| `AUTO_BED_LEVELING_BILINEAR` | включено, сетка 5×5 | Билинейная калибровка стола |
| `Z_SAFE_HOMING` | включено | Парковка в центре стола перед homing по Z с помощью датчика |
| `Z_MIN_POS` | `-5` | Позволяет соплу опускаться ниже Z=0, чтобы действительно касаться стола при отрицательном Z-смещении |
| `Z_MAX_POS` | `350` | Физическое удлинение оси Z («Z350») — **не** уменьшайте до стандартных 250 |
| `PROBING_MARGIN_LEFT/RIGHT` | `35` | Удерживает смещённый датчик в пределах стола |
| `BABYSTEP_ZPROBE_OFFSET` | включено | Оперативная подстройка Z-смещения во время печати |
| `PROBE_OFFSET_WIZARD` | включено | Калибровка Z-смещения через мастер на LCD |
| `BINARY_FILE_TRANSFER`, `CUSTOM_FIRMWARE_UPLOAD` | включено | Возможность бинарной передачи файлов Marlin (см. ограничения ниже) |
| `M936` | включено | Обработчик команды Creality MCU-OTA (для совместимых плат) |

## Сборка

Требуются Python 3 и PlatformIO:

```bash
python3 -m venv .venv
.venv/bin/pip install platformio
.venv/bin/pio run -e STM32F103RE_creality
```

Бинарный файл создаётся по пути
`.pio/build/STM32F103RE_creality/firmware.bin`.
Готовые к прошивке копии находятся в [`firmware/`](firmware/).

## Прошивка (требуется SD-карта)

1. Скопируйте **один** файл прошивки `.bin` в корень SD-карты с файловой системой FAT32.
2. Переименуйте его в **новое уникальное имя** — загрузчик Creality 4.2.7 запоминает
   предыдущее имя и не прошивает то же имя повторно.
3. Убедитесь, что на карте **только один файл `.bin`**.
4. Выключите принтер, вставьте карту, включите питание и дождитесь завершения
   обновления (экран может ненадолго погаснуть).
5. Извлеките SD-карту и перезагрузите принтер.

Проверьте командой `M115`: должно отображаться **Marlin 2.1.2.10** и дата сборки.

## Первая калибровка после прошивки

1. `M502`, затем `M500` — сбросить настройки к значениям прошивки.
2. `G28` — парковка всех осей; `M401` / `M402` — выпустить/убрать CR-Touch.
3. Установите Z-смещение, например `M851 Z-1.38`, затем `M500`.
   Либо используйте мастер на LCD: **Motion → Bed Leveling → Probe Offsets (Wizard)**.
4. `G29` — построить сетку, затем `M500` для сохранения.
5. Тонко подстройте первый слой во время печати с помощью babystepping.

Устранение неполадок — в [CR-TOUCH-BUILD.ru.md](CR-TOUCH-BUILD.ru.md).

## WiFi-бокс Creality

Бокс в сети можно использовать для **мониторинга и управления G-code**
(HTTP API состояния на порту 81, анонимный FTP к его SD-карте, telnet-доступ).
Учётные данные устройства намеренно не приводятся в этой документации.

**Обновление прошивки через бокс на этом оборудовании ненадёжно:**

- Встроенный MCU-OTA бокса отправляет `M936 V2`, ожидает `mcu reset ok`, затем
  передаёт прошивку. На плате 4.2.7 загрузчик не переходит в режим OTA, поэтому
  передаваемые байты воспринимаются Marlin как недопустимые команды.
  В оригинальной прошивке Creality 4.2.7 обработчика `M936` нет.
- Путь бинарной передачи Marlin (`M28 B1`) был опробован с прототипом uploader'а
  с повторной отправкой. Большинство пакетов проходит, но демон бокса `prt_com`
  добавляет в последовательный поток свои опросные команды `M105`/`M27`,
  повреждая пакеты. Надёжного uploader'а пока нет.

Поэтому **для обновления прошивки используйте SD-карту**. Для мониторинга и
калибровки через бокс проблем нет.
